Day 3Orchestrate · Measure · Experiment

Hand the Funnel to an AI Agent, Then Prove Every Number

This is where the system becomes agentic. Claude Code takes over the running of your funnel through each tool's API or MCP server, one dashboard shows every number from the first touch to the cleared payment, and a weekly loop replaces one page or template at a time and keeps the winner. What you leave with is a revenue engine that improves itself every week.

Claude Code is the worked example. Any agentic coding tool that supports MCP works the same way.

When: Steps 1 to 5 happen now. Steps 6 to 8 happen after your first run finishes (your event date from Day 1 Step 7), because they read that run's numbers.

Step 1: Connect Claude Code to Every Tool

Task 3.1Connect Claude Code to Every Tool

Why: Claude Code can only run what it can reach. Connected to each tool, it reads live numbers, makes changes, and answers your team from real data instead of memory.

  1. Install Claude Code (docs.anthropic.com/en/docs/claude-code). It needs a paid Claude plan or API billing. Open it in one folder that holds your Day 1 decisions (offer, persona, funnel choice, webinar date), your Day 2 assets, and a .env file with the credentials from Day 1 and Day 2.
  2. Connect Tantra: create a dedicated API key (see usetantra.com/developers). Then follow the MCP Server page to add Tantra to Claude Code with claude mcp add, over hosted HTTP or local stdio, and ask it to call whoami to confirm. Keep the same key in .env for REST API calls.
  3. Add every other tool from the table below. One key or token per tool, all in .env, never pasted into the chat.
  4. Create one Google service account: in Google Cloud, IAM & Admin → Service Accounts → Create service account. Open it, then Keys → Add key → Create new key → JSON. Save the file in the folder and its path in .env.
  5. For Sheets and GA4: enable the Google Sheets API and the Google Analytics Data API in that Google Cloud project. Then in GA4, open Admin → Property access management, add the service account's email and give it the Viewer role.
  6. Test it. Ask: "List my Tantra campaigns with sends, RSVPs and replies for the last seven days." The answer must match Tantra's own dashboard.

Example: for a software company on route B, the folder holds the Day 1 and Day 2 files, a Tantra key, the Cloudflare API token from Day 1 and one Google service account that covers Sheets and GA4.

Step 2: Brief It Before It Changes Anything

Copy This as Your First Message

"Read every file in this folder in full. Confirm you've read them. Then interview me, a few questions at a time, about brand and story, offer and pricing, buyer, traffic channels, and the tools connected here. Wait for my answers. Then write one spec file that holds every page, template, price and automation, and restate it for my approval. Do not change anything live until I approve it."

Task 3.2Run the Interview, Then Approve the Spec

Why: What you give the agent before you ask decides whether it runs your funnel or a generic one. Having it write the spec and restate it gives you one cheap chance to catch a misunderstanding before anything live changes.

  1. Send the prompt above as your first message.
  2. Answer honestly. "I don't know yet" beats a made-up answer.
  3. Read the restated spec line by line and correct it.
  4. Approve. From then on every change goes into the spec first, and Claude Code applies it to the live pages and campaigns. On route A, GoHighLevel page content can't be edited through its API, so Claude Code gives you the page changes to paste in, and applies the rest itself.

Example: for a course business, the interview catches a cohort start date that differs between the landing page and the reminder email.

Step 3: Check Every Automation Fires

Task 3.3Prove the Automations With a Real Contact

Why: The automations built on Day 2 do the follow-up nobody remembers to do. One that never fires loses leads silently, and you only notice weeks later on the dashboard.

  1. Ask Claude Code to fill the automation register (the template under this step in the onboarding centre): each automation's trigger, action, tool and honest status. On route A they are GoHighLevel workflows; on route B they are Cloudflare Workers.
  2. Point Tantra's outbound webhooks (RSVP, reply, bounce, unsubscribe) at your workflow or Worker, so every response lands on the contact. Webhook setup is documented on usetantra.com/developers.
  3. Test three automations from the diagram: 1 (confirmation and reminders), 3 (your own page's form) and 4 (the webinar attended or live webinar not watched tag). Use a short test session (10 minutes in Zoom or WebinarGeek): register yourself and attend, register a second address and don't show, then refresh attendance in Tantra.
  4. Ask Claude Code to read both contacts back and confirm every tag and stage.

Example: for a consultancy, the no-show test shows the replay email firing but the live webinar not watched tag missing, so the next-day follow-up never sends.

Step 4: Build the Dashboard

What it shows: one row per run and per source, with every count from first touch to sale: sends or invites, RSVPs, landing visits, registrations, attendees, CTA clicks, calls booked, sales, revenue, and the page variant. Rates sit between each pair. Where it lives: a Google Sheet in your Drive, copied from the Per-Run Session Analytics Sheet template (under this step in the onboarding centre). Tantra's own dashboard keeps the outreach detail; the sheet is where every tool's numbers meet.

Task 3.4Build the Dashboard and Let It Fill Itself

Why: The dashboard is how you find the leak. A number that isn't on it gets guessed, and a guessed number becomes a fact in next month's review.

  1. Copy the template into your Drive and share it with your service account.
  2. Tag every link with UTMs, using utm_content for the page or template variant. Install GA4 and Microsoft Clarity (both free) on every page.
  3. Ask Claude Code to write the job that fills one row per run from Tantra, GA4, your CRM and Dodo Payments. On route B, schedule it nightly with a Cron Trigger; on route A, ask Claude Code to run it before each weekly review.
  4. Walk the funnel on your phone as a test contact, run the job, and check your row. Leave a cell blank rather than estimate it.

Example: for a consultancy, the cold calendar run and the LinkedIn run sit on separate rows, so the cost per booked consultation for each channel is side by side.

Step 5: Send One Small Test Run

Task 3.5Send One Small Test Run

Why: Until strangers go through it, every page and template is a guess. A small run keeps being wrong cheap and gives the dashboard its first real row.

  1. QA first: every page at 375, 768 and 1280px, one real purchase, every dashboard column filling.
  2. Launch the smallest version of each live channel, every link UTM tagged, all pointing at one registration page. Cold email and calendar invites wait until the Day 1 inboxes have warmed for 2 to 3 weeks (about the week after your workshop); until then, run LinkedIn inside its daily caps and email people who already know you.
  3. Read nothing until the run has finished. Numbers read after a few hours kill things that were working.

Example: for a course business, one LinkedIn batch and one email to past course buyers feed the same session; cold calendar invites join once warm-up is done.

Step 6: Read the Dashboard and Find the Worst Step

Task 3.6Name the One Step to Fix

Why: The weakest rate is where the week's work goes. Change five things at once and you can't tell which one moved the number.

  1. When the run finishes, read five numbers: registration rate, show rate, CTA click rate, buyers, and cost per buyer.
  2. Compare each rate with the rest of your funnel and with the last run. The lowest, or the one that dropped, is the worst step.
  3. Find that row in the table below. It names the one page or template to swap.
  4. Put your fetched numbers into the calculator to see cost per buyer against lifetime value.

Example: for a software company, most registrants show up but almost nobody clicks the CTA, so the offer slide gets swapped, not the reminders.

Step 7: Run the Experiment Loop Every Week

Task 3.7Swap One Thing, Read the Dashboard, Keep the Winner

Why: One swap per week, judged on the dashboard, is how the funnel improves without guessing. The worst step moves once you fix it, so this is a weekly habit, not a project.

  1. Ask Claude Code for one variant of the element the table named: a second landing page, or a second version of the Tantra step template.
  2. Split the next run in half. Half the list gets variant A, half gets B, each link carrying its own utm_content, so the dashboard counts them separately.
  3. When the run finishes, read both rows. If the gap is only a handful of people, run the same test again before you call it.
  4. Keep the winner, revert the loser in the spec, and log the change, the date, the metric you expected to move and the result.
  5. Put the weekly review in your calendar as a recurring event.

Example: for a software company, variant B's headline names the integration buyers kept asking about. B wins on registration rate, becomes the page, and next week's experiment moves to show rate.

Step 8: Write the Scale Plan

Task 3.8Write the Scale Plan

Why: Five lines on one page turn the dashboard into next month's decisions. The first two must be fetched numbers, not estimates.

  1. My cost per buyer is ___ and my lifetime value is ___.
  2. My cheapest channel by cost per buyer is ___, so next month's budget moves toward it. Keep a small test budget on every other channel.
  3. My worst step is ___ and this week's experiment is ___.
  4. My ascension offer is ___: the rung above what they just bought.
  5. My retention mechanism is ___: what produces the first win, and by when. Everyone else stays warm through the five tags (webinar registrant, webinar attended, live webinar not watched, watched webinar replay, purchased): each tag triggers its own follow-up.

Example: for a consultancy, line 3 reads "show rate; this week we test a WhatsApp reminder at one hour before."
