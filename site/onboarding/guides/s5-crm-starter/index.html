Set It Up With the Starter CRM and Claude Code

Path B: a small CRM you run from a folder; Claude Code connects your forms, calendar, payments and messages.

1The Full Setup
2The Task

Run your pipeline from a folder on your own computer instead of a subscription CRM. The starter CRM already stores contacts, records events and moves deals through the eleven stages on its own. You paste six prompts into Claude Code to connect your form, calendar, payments and messages. You're done when a real booking and a test payment move a contact through the pipeline and its follow-ups send without you.

3Step by Step
  1. 1
    Get the Starter CRM

    Download the folder: crm-starter.zip ↗. Unzip it into your workshop folder and open a terminal there. Inside:

    • pipeline.json: the eleven stages, the No Show exit, the entry event for each, and the front stages for your mechanism
    • fields.json: the tags and fields, with the same names as every other guide
    • crm.py: the core, with no installs needed (Python 3 only)
    • prompts/: the six Claude Code prompts that connect it to your tools

    The README's status table says honestly what's built and what you build with the prompts.

  2. 2
    Walk a Test Contact Through It

    Run these one at a time (on Windows, type python instead of python3):

    1. python3 crm.py init
    2. python3 crm.py add you@example.com --mechanism webinar
    3. python3 crm.py event you@example.com form.submitted
    4. python3 crm.py event you@example.com booking.created
    5. python3 crm.py event you@example.com booking.no_show
    6. python3 crm.py board

    The deal is in No Show with the call-no-show tag, and you never moved it. Tools report events; events move deals. That's the whole design.

  3. 3
    Connect Your Forms and Calendar (Prompt 01)

    Open Claude Code in the crm-starter folder and paste prompts/01-intake.md. Fill in the two tool names it asks for. Claude reads the folder, finds your tools' API docs, asks you to put each key in .env (never in the chat), and builds intake.py, which checks for new submissions and bookings every 5 minutes.

    It polls rather than waiting for webhooks, because a CRM on your own machine can't be reached from the internet.

    Tip Keys go in .env, which is already git-ignored. Never paste a key into a prompt.

  4. 4
    Connect Payments (Prompt 02)

    Paste prompts/02-payments.md and name your payment provider. Claude builds payments.py, which confirms each payment with the provider's own API, never with the browser, and records payment.succeeded. The CRM adds purchased and moves the deal to Payment Completed. Prove it with one test-mode payment.

  5. 5
    Start the Follow-Ups (Prompt 03)

    This one needs the follow-ups/ folder you generated in Reminders and Follow-Ups for Every Stage. Paste prompts/03-follow-up-runner.md. Claude builds runner.py, which schedules each stage's steps when a deal enters it, cancels them when the person replies, books or moves on, and sends what's due every 5 minutes by email, SMS or WhatsApp, only on channels they agreed to.

    Run python3 runner.py --dry-run and read the next 24 hours of messages before you switch real sending on.

  6. 6
    Add the Extra Pipelines, a Board and a Schedule (Prompts 04 to 06)
    • 04 adds the four extra pipelines next to Sales.
    • 05 builds a local board at http://localhost:8765, with columns in pipeline order and one card per deal.
    • 06 makes intake, payments and the runner run every 5 minutes on their own, and writes a daily 08:00 summary of new leads, moves, sends and anything stuck.

    When all six are done, update the README's status table. Nothing in this setup depends on a third-party automation platform.
